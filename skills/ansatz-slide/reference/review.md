# 审阅与交付实际演示文稿

先串读整稿主线，再检查实际渲染页面，最后核对交付文件。CLI 检查源文件与文件包，
不判断科学含义、视觉层级或听众是否理解。这些检查不增加审批步骤。

## 协作验收责任

按[逐页协作](content/subagents.md)制作时，页面负责人先完成本页源稿预检、文字
容纳测量及修复，携当前报告交回；工具受阻与公式等未验范围如实标明。主 Agent
回收后核对检查产物，再审查源稿的证据、
解释和全局衔接，再统一导出。页面 subagent 的自检结果只提供线索；主 Agent 须
检查实际源稿及必要原始材料，不能只收“完成”。页内问题交回该页负责人，主线或
前提问题由主 Agent 修订规划并通知受影响页面。批量最终渲染由主 Agent 组织复用。
批量最终渲染用于减少重复工作，不允许将本页文字检查也推迟到整合后。

## 渲染前先检查源稿与素材

首次生成前，制作 Agent 先运行[源稿预检](production/cli.md#源稿预检先于-pptx-与渲染)，
处理现有 `page.yaml` 和引用素材中能确定的问题，再生成 PPTX；不另建一份必填表单。
预检支持未导入候选，局部修改只检查受影响内容。

- 标题是否已写成“章节: 页标题”，章节和主题是否简洁；核心总结是否串得通。
- 通常第 2 页是否已交代背景、已有工作的具体缺口和本文要处理的问题？各页之间
  是否有理解与论证上的推进，是否仍需演讲者补出大段隐藏前提？先检查提纲和源稿，
  再生成与渲染；结果数字与流程概览不能替代背景交代。
- 正文、bullet、图旁解释、描述性图注和总结是否完整成句？在源稿阶段逐项核对
  对象、动作及逻辑联系，先改掉关键词堆砌和流水账短语，再生成 PPTX。技术标记
  按 `content.md` 的表达边界处理；句号本身不能证明句子完整。
- 本页用到的方法、结论、图和公式是否已经配上可读的论文式文献条目。
- 本页需要的公式是否有实际元素及存在的排版素材，符号说明是否齐全；正文、表格
  和图注中的上下标是否与公式一致？数学符号及单位是否已正式排版，而非以 Unicode
  字符、普通拼接或 HTML 上下标替代？具体方式见[公式说明](production/equations.md)。
- 元素、文字量与区域尺寸是否匹配；少量文字占据巨大框等明显问题先调整布局。
- 裁图在素材阶段核对坐标、单位、图例、必要边界与邻图残片。几何检查只看到图片
  的外框，无法据此确定图片像素里的内容；复用已检查且未改动的同一素材。

CLI 在源稿阶段检查字段、几何与素材，并提示标题、引用、普通数学记号、Unicode 数学字符、疑似缺公式
及稀疏大框；句子完整性、其他语义和图片像素内容仍由制作 Agent 判断，图像边缘碎片检测尚未实现。
不能把提示通过当成语义验收。后续文字测量与最终渲染用于确认实际
软件中的换行、字体、公式、图片和布局，不替代这轮源稿检查。

## 三层检查及复用

1. 程序直接检查边界、越界与未声明重叠，失败时返回问题元素和位置；矩阵只在显式排障时生成，不交给 LLM 逐格阅读。
2. 程序测量文字是否放得下，多页任务批量测量、批量渲染。小幅 PDF 字体度量越界按需用栅格字形复核；实际字形完整位于框内才能通过，不自动缩字或移位。结构和文字检查通过后，视觉状态仍是未验收。
3. Agent 打开实际 PPTX 渲染图，检查层级、留白、字体、图片裁切与可读性。默认用少量可读拼图批量覆盖各页，仅对问题页或需要确认的关键细节单独放大；不凭程序 passed 宣称视觉合格。

同一版本已有最终渲染时直接复用，避免重复调用渲染器。修改后检查新版本受影响页；共享素材、字体或页面顺序改变时检查相应范围。源文件预览不能充当不同版本交付文件的证据。

减少看图与渲染往返：已有旧稿证据时 `deck open --no-preview`；制作完成后优先复用
CLI 返回的最终 PPTX 渲染，一次生成可读拼图，批量检查整稿，避免逐页单独打开。
拼图发现疑点后才单独查看对应页或局部，修改后只重新查看受影响范围。CLI 若已
重渲染全稿，直接使用其结果，不额外运行一次渲染器。拼图应足以阅读所检查内容，
小到只能看配色的缩略图不承担字体、公式与引文检查。

## 同一版本的审阅入口

`deck revise` 返回 `review.viewer`（本地 HTML）和 `review.manifest`（JSON），集中展示
实际页面、对应源文件、程序检查和问题。项目级计划还显示失败候选；界面明确区分
候选与交付，不把旧图片混入新版本。几何受阻时图片为空，仍可定位问题。

在查看器中按修改页或问题页筛选，再用单页大图审阅。
查看器逐页显示源稿预检提示，并将其纳入“有问题的页面”筛选；提示与阻断问题
分开显示。Agent 须逐项核对，警告本身不阻断导出，也不代表视觉或科学内容已通过。
记录观察使用
`deck review DIRECTORY --page N --status reviewed|needs_fix --note TEXT`。
程序检查、已查看页面、尚待修正分别保存；`reviewed` 不表示科学内容已获程序认证。
命令核对源文件与 PPTX 字节，拒绝给已变化的版本追加旧审阅记录。
操作与示例见[项目级计划](production/cli.md#项目级修改计划与统一审阅推荐)。

## 逐页检查

先看完整页面，尝试指出本页最重要的对象、支持结论的具体证据，以及两者之间的
关系。若只能复述标题，却找不到相应证据位置，或必须自行补出关键定义，页面仍
需要修正。随后以可读尺寸查看重点区域，同时检查解释与阅读顺序：

- 标题或问题是否对应可见材料？听众能否在没有额外阅读报告的情况下理解推理、
  定义与条件？
- 顶部是否采用“章节: 页标题”，章节定位和主题是否清楚，是否堆成多个主谓宾分句？
  概览页是否有清楚的关系组织，是否出现几个短语占满三个大空框的布局？
- 标题以外的讲解文字是否仍是完整句子，排版精简是否删掉了必要的主谓或联系？
- 图中面板、公式项与物理对象是否对应？图注、箭头和标签是否指向正确对象？
- 逐页对应实际内容检查：本页讲解或推理所需的公式是否已从源表达式制作并插入，
  符号、单位和适用条件是否足够？前页公式、论文截图和图轴小字不能代替当页公式。
- 本页每个外部方法、同行结论、数据、图及公式是否有可读的论文式文献条目？只有编号、
  模型名、作者年份、备注或末尾文献表视为外部来源当页引用未完成。
  按content.md逐条核对作者顺序、原始题名、刊物、卷页年及DOI等适用字段；不将
  通讯作者拼进简写作者表，不用自拟主题替代论文题名。被汇报的主论文免逐页重复
  引用，定位保留在备注；外部补充与论文成果应能区分。
- 文献初稿是否按出版记录完整列出作者？未经用户明确指定，不自动使用et al.、
  “等”或选择省略名单；作者较多时先安排版面，再由人类调整简写。
- 讲解所需的模型图、数据图是否已提供，或已在页面中明确占位？占位是否有用途、
  内容规格及数据／来源线索，能否让人或另一个 LLM 直接接手替换？
- 新制作的数据图是否与输入、处理方式和结论一致，示意图是否忠于所讲版本？
  是否保留[各绘图路线](production/figures.md#检查与交付)的可修改源稿，并在实际
  PPTX 放置尺寸下检查字体、箭头、坐标和裁边？
- 文字密集页增加示意图后，听众是否能直接看出原先需靠大段文字解释的关系？
  重复说明是否已精简，背景、研究问题与必要条件是否保留？概念点阵、节点或
  表征图形是否被误读成比例、真实结构或实验数据？
- 主证据是否足够大？读完每个文字块，核对图的四边、刻度、坐标、单位、图例
  与必要限定。
- 字体、对比度、对齐与间距在投影距离下是否可读？放大查看能帮助诊断，不能
  让投影时过小的文字变得合格。
- 裁切或蒙版是否遮挡必要证据？强调是否帮助理解？留白与有意重叠可以合理使用。
- 尽量避免文字、框线、图注与页码的意外碰撞，留出安全边距。人类 case 中偶有的
  轻微碰撞不作为复刻目标；有意的框内标签等叠放仍可保留。

把判断落到具体页面：说“这里出现分离”，就检查能否直接找到分离位置；说“半径
对应熵”，就检查对应关系是否得到必要解释。检查分区框是否表达清楚的概念，
箭头与颜色是否帮助定位证据，以及空白能否用于放大目前难读的主图。无需为每页
填写评分表；发现问题后修改相应图文组织，不能仅以无碰撞、字体放得下作为完成依据。

解释不清时参考[页面示例](content.md)，数学内容参考[公式说明](production/equations.md)。
必须打开实际图片，路径、坐标和成功命令不能代替看图。

## 修正具体问题

定位页面和问题，采用最小有效修正，再查看新渲染。工作笔记简单记录即可，
例如“第 6 页纵轴文字被裁切；扩大裁切范围后已完整显示”，不要求评分表。

通过[页面操作](production/cli.md)修改相关源文件。可以一次打开并修改多个目标页，
但要逐页检查新渲染。保留已经接受的内容。共享字体、素材或前提改变时扩大检查。
源材料本身不一致时保留并说明，不默默修改其科学含义。

按问题回到对应位置，不对所有失败都重新生成整稿：

| 问题 | 修正位置 |
| --- | --- |
| 缺定义、证据不支持表述、页面转折跳跃 | [内容组织](content.md)，回读材料并调整受影响的讲解 |
| 标题拥挤、主图太小、层级或对比不清 | [唯一风格](style.md)，先调整布局，再酌情缩字或拆页 |
| 字段不支持、导出或渲染失败 | [制作与修改](production.md)及[技术参考](technical.md)，依据具体诊断修复 |

## 整稿检查

抽出各页的核心总结句，按页序连读，检查能否组成完整论证：前提、方法、发现与
结论是否逐步推进，转折是否有理由。再检查标题、正文与总结中是否堆积否定、双重
否定或反驳式句型；按[学术表达](content.md#学术表达直接陈述发现与条件)直接陈述
发现及其适用条件。保留必要负结果与关键限定，修正用通用风险提醒代替页面总结的
情况；这项检查针对语义与整稿阅读，不按否定词数量机械判定。

依次阅读实际标题和页面，检查缺失前提、重复内容、符号变化、比较条件不一致，
以及结论与用户明确要求不一致的情况。发现证据疑点时指出，不自行替换人类结论。
结尾是否回应报告目的，或明确指出尚未解决的问题？
连续页面采用同一布局时，检查它是否支持各页的讲解关系；重复本身不构成错误。
核对页数是否满足讲解与用户限制，而非继承测试案例的篇幅。
必要时参考[内容 guide](content.md)。

缩略总览用于观察节奏与密度；可读拼图可批量检查各页，疑点与复杂细节再放大。新报告检查整稿；
局部修改检查相关页及其前后衔接，不重新启动整个报告。

## 交付

- 交付请求的 PPTX、清单、引用页面源文件和本地素材。保留有关的内容意图与用户
  要求，说明缺失素材或剩余远程依赖。
- 核对最终文件页数、顺序和结构检查结果。`deck export` 已检查结构，`deck revise`
  还会渲染最终文件；复用已有结果，不无故重复同一检查链。
- 检查确切交付版本的渲染，不能只看旧源文件预览。修改后更新相关页面的渲染证据。
- [二进制单页替换](production/replace-page.md)须核对非目标页保护报告并查看合并结果。局部替换
  失败时不能用全量覆盖代替。
- 学术报告通常无元素动画，并使用 `--transition none`。用户需要动画时单独检查
  播放。字体不嵌入，需检查所选引擎的字体显示。
- 含必要素材占位时标明仍待补图的页码及内容，作为待补素材版本交付；不能将其说成
  全部内容已完成。占位位置已通过布局检查，与相应科学图和结论已验收是两件事。

返回文件时简洁说明实际检查、渲染器、查看过的页面及影响使用的限制。区分通过、
失败、未运行和受阻。不能把清单、导出成功或其他 Agent 的声称当成视觉与内容
验收。未被要求时无需长日志，有用的诊断保留在工作目录。

## 渲染引擎

Deckcraft、LibreOffice、Microsoft Office（PowerPoint）三选一作为本次实际 PPTX
的渲染与视觉验收引擎。用户指定时遵从用户，否则选择可用的引擎；一次任务保持一致。
不要求三种引擎全部检查。记录所选引擎和检查范围，不把单一引擎结果说成跨软件验证。
若所选工具不能渲染实际交付 PPTX，则不能用源文件预览替代；应说明限制并选用可用引擎。

当前 CLI 内置预览与文字测量使用 LibreOffice/Poppler。三选一是视觉验收规则，
不代表 CLI 自动预览支持三个可切换的渲染引擎。`--backend` 只选择创建后端；具体运行依赖见[制作与修改](production.md#渲染依赖)。
