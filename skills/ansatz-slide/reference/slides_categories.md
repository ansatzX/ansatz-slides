# Scenario guide

Choose one primary scenario from the task's reader objective. Read only that file; add an auxiliary scenario only when it contributes necessary guidance. Named presets and user references are selected through SKILL.md, not automatically through this table.

[Skill working rules](../SKILL.md) defines hard constraints and priority. The files below describe communication methods and visual defaults; they do not add DSL features, impose mandatory research, or override a user's visual system.

| Scenario | Reader objective | Guide |
| --- | --- | --- |
| Analysis and decision | Compare evidence and options; make a decision | [Analysis](slides_categories/analysis-decision.md) |
| Business proposal | Understand value, feasibility and the ask | [Proposal](slides_categories/business-plan.md) |
| Management reporting | Understand progress, deviations and actions | [Reporting](slides_categories/management-report.md) |
| Academic research | Evaluate question, method, evidence and limits | [Research](slides_categories/academic-research.md) |
| Education and training | Learn a concept or perform a task | [Training](slides_categories/education-training.md) |
| Tech and engineering | Understand mechanisms, dependencies and trade-offs | [Engineering](slides_categories/tech-engineering.md) |
| Brand and creative showcase | Recognize the subject and understand the creative proposition | [Brand](slides_categories/brand-creative.md) |

Shared production defaults: one primary reader task per page, clear hierarchy, appropriate density, readable evidence, nearby sources and stable semantic colors. Tables/figures come from the user or external tools; native text/shapes/lines frame and annotate them. Use labeled placeholders when needed. Rendering checks belong to [delivery-checks.md](delivery-checks.md), not separate scenario-specific export procedures.
