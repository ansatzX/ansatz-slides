# Environment and command entry points

Use Python 3.11+ and the pinned PyYAML 6.0.3 dependency. Pure JSON inputs can be parsed without PyYAML, but formal files generated by the CLI contain YAML comments and need the normal dependency installation.

## Repository checkout

```bash
mkdir -p tmp/uv-cache tmp/test-tmp
export UV_CACHE_DIR="$PWD/tmp/uv-cache"
export TMPDIR="$PWD/tmp/test-tmp"
uv sync --frozen
uv run --frozen ansatz-slide --help
```

With dependencies already installed, `PYTHONPATH=src python3 -m ansatz_slide` is another entry point. Use [the starter](authoring-start.md) for runnable input and [the work-object reference](review-cli.md) for authoring commands.

## Standalone Skill

Install from the checkout into a skills parent directory:

```bash
uv run --frozen ansatz-slide install-skill --target ./tmp/skills
```

The generated `ansatz-slide/` contains instructions, `python/ansatz_slide`, templates, scripts and a locked local environment. From that installed directory:

```bash
mkdir -p tmp/uv-cache
UV_CACHE_DIR="$PWD/tmp/uv-cache" uv sync --frozen
uv run --frozen python scripts/ansatz_slide.py --help
```

Replace the target with the intended skills parent directory. Replacing an existing installation requires `--force` within user scope. Installations copy the current package; later checkout edits do not update an already installed Skill. Finish old CLI writers before upgrading, particularly when switching locking protocols.

## Rendering dependencies

Page creation/open/update previews use LibreOffice (`soffice` or `libreoffice`) and Poppler (`pdftoppm`, `pdftotext`, `pdffonts`) on PATH. The CLI does not install them. Missing tools or a render failure retain candidate work and prevent its publication; retry the returned work when the dependency is available. `--width` on page open sets preview resolution.

`validate`, legacy `export`, `inspect`, and `page check-overlap` do not require Office rendering. `deck export` and page previews now require Office for native text measurement. Export success is not visual review. Formula image generation has separate dependencies in [equations](equations.md).

## Export and inspection

```bash
ansatz-slide validate ./deck
ansatz-slide deck export ./deck -o ./result.pptx --offline --transition none
ansatz-slide inspect ./result.pptx
```

Use actual paths. `deck export` defaults to no transition; the older `export` and `replace-page` commands default to fade. `--transition` controls slide transitions, not element animations. Fonts are not embedded.

Existing output requires `--force`. It controls output replacement only, never bypasses schema or geometry checks. Output must not replace source files or referenced assets. `--offline` rejects remote images; otherwise export may fetch explicitly referenced HTTP/HTTPS assets. Page previews require local or data-URL assets. All local paths must stay within the project.

Use [page replacement](page-edit.md) when preserving the other pages of an existing PPTX. For final evidence and handoff, follow [delivery checks](delivery-checks.md). Legacy session/token integration is documented separately in [compatibility commands](review-cli-legacy.md).
