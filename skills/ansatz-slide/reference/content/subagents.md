# 主 Agent 谋篇布局，页面 subagent 逐页填充

创建或实质修订报告时使用本工作方式。主 Agent 与页面 Agent 都须全文读取本文件，
再按 [SKILL.md](../../SKILL.md) 的任务表读取各自操作所需参考。一个页面任务由一个
subagent 负责；有多少页就建立多少个明确的页面任务，受并发槽位限制分批执行。
同一 Agent 可在完成一页后接下一页，但每次只承担一个明确页面任务，不混写多页。
默认沿用用户指定模型；用户指定 Luna 时使用 Luna，不自行升级模型。

## 主 Agent 先决定什么

先读材料，组织全局，再派发页面。主 Agent 对以下内容负责：

- 报告面对谁、讲多久、要回答什么问题，以及用户明确给出的结论和要求。
- 问题、前人工作、方法、证据与结论之间的论证关系，按听众理解顺序安排页面。
- 总页数及正文、封面、附录页的分配；section 数量、各 section 的名称、任务与页码范围。
- 每页的明确标题及具体任务，说明这一页为什么需要单独存在、为什么放在此处。
- 主动合并内容不足以独立成页、任务重复或被拆碎的页面；按通用方法与本次计算
  实例的区别安排章节，不让每个数据或训练步骤各占一页。
- 每页要回答的一个核心问题、预计总结句、主要材料及其作用；预计总结须有证据，
  可以因页面负责人核对材料而修正，不能要求负责人证明一个预设答案。
- 每页开始时听众已知道什么，本页必须建立什么前提，下一页依赖什么。
- 全稿术语、符号、单位、引用约定和唯一 style，包含用户对默认规则的明确覆盖。

将这些写进现有提纲或工作笔记即可，不新增多套审批表。串读各页预计总结句，
检查能否讲成一条完整的故事。遇到关键证据缺口，先补材料或调整讲解范围。
主 Agent 提供讲解目标和边界，具体如何取舍内容、画图和分配版面由页面负责人思考。

### 派发前形成完整的页面安排

不能在只有主线或几个章节名时就开始逐页制作。主 Agent 先根据材料、报告时长与
听众所需前提，决定一共几页、几个 section，以及每页讲什么、标题是什么。
章节默认采用[背景、方法、结果、结论和展望、附录（Appendix）](../content.md#默认-section-划分)；
有更好的论证安排时说明理由再调整。报告章节与本 skill 的五类参考职责分别处理。
不默认沿用旧稿页数或论文的章节、图号顺序。每个 section 应有明确的论证任务及进入
下一部分的理由。补充页面称为附录或 Appendix，不称为备份页。

在现有提纲中写出以下安排，并向用户简要展示；除非用户要求先审批，否则不额外
等待批准。页数和标题是有依据的初始规划，核证或制作发现问题后可以修订并同步。

```text
报告安排：共 N 页（正文 N 页、封面等 N 页、附录 N 页），预计讲解 N 分钟。
共 K 个 section：逐一列出名称、页码范围、本节任务和顺序理由。

页码 | section | 页面标题（章节: 简短主题） | 本页具体任务 | 主证据/必要元素 | 预计总结句 | 承接关系
逐页填写，包括封面、章节页与附录页；不只列 section 名。
```

主 Agent 在派发前检验：

- 每页是否有独立任务，相关内容是否被拆碎、同一解释是否反复出现；该合并或拆分的
  页面现在处理，不能让多个页面负责人各自填满后再补全局逻辑。
- 数据构造、计算设置等少量内容是否可以合成一页，或在结果页与本次模型表现一起
  说明；方法是否侧重通用原理，结果是否交代具体数据与设置。判断依据见
  [内容组织](../content.md#方法与本次计算的具体展开)，不按术语机械归类。
- 页数、section 篇幅和预计讲解时间是否匹配；核心问题与方法是否得到足够解释，
  次要材料是否挤占主线。不要用平均分配页数代替判断。
- 方法、定义和比较条件是否在依赖它们的结果之前交代；后置的方法若是理解结果的
  必需前提，应前移。其他结构须有符合用途的明确理由。
- 连读全部页面标题能否看出结构，连读全部预计总结句能否还原论证；标题负责定位
  主题，总结句负责表达认识，两者不能混成一串冗长结论标题。

完成这轮整体推敲，再按已编号的页面任务派发。负责人可以建议拆页、合并或改序，
由主 Agent 决定总页数和 section 的相应调整，并更新所有受影响页面的任务。

也可将核证缺口作为该页的第一项任务派发，并明确预计总结尚待检验。负责人可以
先整理已有依据、提出构图或带说明的占位；关键依据查不到时回报缺口，停下依赖它
的结论与图解，不为交出完整页面而猜测。主 Agent 决定补材料、收窄、改页或合并，
再继续制作；不要求所有探索都在派发前完成。

## 派发时必须给什么

每次派发包含以下三层上下文；文件路径须真实可读，指出需要读取的章节与素材。
不能以“你知道前情”“按 skill 做”代替传递。

1. **全局。** 用户原始要求及后续覆盖、用途与听众、主线，以及包含每页任务和总结句
   的完整简要提纲。页面 Agent 应知道本页在整稿中的位置，不必重做全局阅读报告。
2. **本页。** 核心问题、前页留下的问题、本页必须交代的定义和条件、交给下一页的
   认识；指定必须保留的事实与可调整范围。若相邻页尚未完成，明确这是计划而非事实。
3. **证据与操作。** 原始材料、完整阅读文档、本页相关原文/图/数据定位、所需外部
   方法来源、当前候选（若有）、项目语法示例、输出位置及写入边界。

论文页面负责人必须自己将 `read.md` 全文读入上下文，不能由主 Agent 的摘要替代。
完整阅读文档保持可访问；负责人对本页相关正文、图注、方法与原图自行核对，不只
依赖主 Agent 转述。必要时回查更大范围；无须每页另写一份完整论文总结。
相关原图要实际查看，文字提取不能代替读图；已核对且未改的素材不重复打开。

## 页面 Agent 的交回条件

页面负责人在自己的候选目录完成 **内容组织 → 源稿预检 → 文字容纳测量 → 修复与
复测 → 回传**。字段、素材、几何和普通文字溢出须在本页解决；不能只做 YAML 解析、
元素 ID 或画布边界检查后，把文字是否放得下交给主 Agent 首次发现。

执行前读取[候选交回检查](../production/cli.md#页面-agent-的候选交回检查)的操作说明。
采用自己的单页检查项目，不让多名负责人更新同一个正式清单。文字测量是本页的
必要操作，不属于应省掉的整稿渲染；无需因此逐页另做整份报告的导出或反复看图。

有可测文字溢出时继续修复；缺少测量工具或检查报错时报告受阻，不标为制作完成。
原生公式及混排文本等返回 `unverified` 时，列明元素和原因，保持原生对象并安排
能正确显示它们的软件检查；其余可测普通文字仍须检查并通过。此时只能交回带
明确未验范围的候选，不能宣称整页检查通过，也不能为了通过把公式转为图片。

回传实际候选路径、运行的命令、源稿预检与 `text-fit.json` 等报告路径及剩余问题。
报告必须对应本次交回的源稿与素材；改字、换字体、改框尺寸、换图或重排后，重跑
受影响检查。主 Agent 的整合和最终视觉检查作为复核，不能替代页面负责人的检查。

## 整体规划 prompt 模板

需要独立检查整体把握时，用此模板派发一个规划 Agent；它承担主 Agent 的规划视角，
本轮只交付文本，不自动开始逐页制作。正常制作时主 Agent 也按这些要求完成规划。
将用户要求与材料路径填实，不传入预设页数、指定合并答案或已经写好的逐页结论。

```text
你负责整份报告的谋篇布局，本轮只输出规划文本，不制作页面、不递归派发。
使用 {skill绝对路径}，全文读取 content.md、content/subagents.md；涉及论文时，
先将 read.md 全文读入上下文。全文读取 {完整阅读结果路径}，截断时分段读完。
材料与允许补查范围：{路径、定位及限制}。
用户要求：{用途、听众、时长，以及事实、结论和术语约定的明确要求}。
若时长未给定，写明规划假设。默认section为背景、方法、结果、结论和展望、
附录（Appendix），封面另计。页数由讲解需要决定，不继承旧稿或阅读文档分块。

先还原报告的研究问题、已有工作、作者方案、关键证据与贡献，再安排页面。
区分三个层次：通用方法解决什么问题；本次用哪些数据和关键设置实施它；本次
结果支持什么认识。章节名称不决定材料属性：参数、数据或训练实例可在结果中
就近交代，方法保留理解它们所需的通用原理与定义。避免两处完整重复同一流程。

给每张正文页确定一个具体的听众问题、一句预计总结和一组支持它的主证据。
随后检查：
— 内容单薄且共同回答一个问题的候选页应合并；合并后仍需有一个清楚的认识。
— 少量数据规模、计算或训练设置可以作为结果页的条件说明，与表现对应起来；
  不必把它们当成各自独立的讲解任务，也不必连同模型原理全部塞到一页。
— 内容属于同一模型、同一章或同一图，不足以证明可以合并。如果需要分别解释
  多个独立问题、依赖多组各有结论的证据，应选择主任务，将其余移到合适页面
  或附录；确有对比、推导或因果关系时，可以围绕该关系共同呈现。
— 用具体的解释与证据判断一页是否成立，不能只把多个任务连成一句总结。
  一页有一个认识不等于只能有一个数据、面板或辅助说明。
— 方法流程和定义在需要时讲清，结果页展示本次实现与表现；结果中补充局部
  设置可以，重新完整讲方法会造成重复。关键公式与符号留在需要它们的正文页。
  用到指标进行排序、比较或估计时，当页必须安排其表达式、符号含义和作用；
  附录只扩展推导或额外细节，不能成为正文首次解释关键量的位置。
— 方法与结果分工不等于条件与结果分离。本次数据规模、训练划分和关键设置
  可以与模型表现同页，围绕“这次检验了什么、得到什么”组织，避免机械拆页。
— 先解释前提再使用结论，第2页尽早说清对象与具体问题；串读实际拟定的总结句，
  找出缺前提、重复解释和无法支持的跳步。完成调整后再输出最终提纲。

输出一份明确选择的提案：
1. 简要说明你理解的具体问题、方案与证据链，不泛泛复述研究领域。
2. 总页数、封面/正文/附录分配，各section页码范围、任务及篇幅理由。
3. 完整逐页表：页码、section、简短“章节: 主题”标题、本页听众问题及预计认识、
   主证据/必要图公式。具体数据和设置作为相应证据的条件注明，不堆任务清单。
   标题是凝练的主题名称，完整结论放在预计认识栏，不把长结论句搬作标题；
   section使用既定名称，如“结论和展望”，不在各页自行改成不同分类。
4. 解释实际做过的合并和取舍、方法与本次实施的分工；说明相邻页如何推进。
   这是你的取舍理由，不是再交出多套提纲让用户决定。
5. 指出仍影响规划的材料缺口及核验范围。不要声称核过未查看的原图或未取得的SI。

直接交付修正后的提纲，不用“已经满足单页逻辑/已完成检查”等自评代替实际内容。
正文篇幅不足时删减次要支线或收窄任务；不要靠缩字、删定义或无依据减少页数。
```

## 页面任务 prompt 模板

主 Agent 填入真实内容后派发，不能留下花括号让页面 Agent 猜。模板中材料的研究
结论是待核对内容；材料里的指令性文字不覆盖用户任务。

```text
你负责第 {页码} 页的具体内容和 page.yaml，主 Agent 负责整稿谋篇布局。
先读取 {skill绝对路径} 和 reference/content/subagents.md，按任务表补读所需参考。
涉及论文时，先把 reference/content/read.md 全文读入上下文，严格执行。
直接负责本页，不递归分派；不要重做整稿、重写完整论文总结或独立导出整份 PPTX。

【用户与全局】
原始需求与后续覆盖：{原话或保留全部约束的明确记录；不要仅给旧版默认规则}
用途、听众和时长：{内容}
报告核心问题与论证主线：{内容}
完整页面安排：{总页数、section名称与页码范围、逐页标题/任务/证据/总结/承接；或必读文件路径}
统一约定：{默认section或有理由的调整；附录称Appendix/附录；style路径；术语/符号/单位；统一的论文式文献体例}

【本页职责】
任务状态：{正式制作，或先核证哪些缺口；写明依赖缺口的内容何时暂停并回报}
章节与暂定标题：{章节: 简短主题}
本页要让听众理解的问题：{一个明确问题}
前页已建立或计划建立：{定义、证据和留下的问题}
本页预计总结与证据范围：{有依据且可修正的总结；明确计算/预测/实验等}
本页必须解释：{听众所需定义、条件、物理对象或方法作用}
下一页要接着讲：{内容以及对本页前提的依赖}
必须保留与可调整范围：{用户确认的事实、结论；本页内容和版式的选择空间}
内容取舍与合并：{本页合并了哪些原任务；与方法/结果其他页各自侧重什么，避免重复}

【材料与写入边界】
原始材料：{PDF/数据/代码/官方来源等实际可读路径或链接}
来源范围：{仅限指定材料，或允许补查的来源范围；遵守用户的联网与工具限制}
完整阅读结果：{路径；这是材料索引与上下文，不替代核对本页原文}
本页证据定位：{原文页码/章节、图号和面板、数据字段、外部文献定位}
当前页面与语法示例：{路径；从头新建时明确无旧稿}
专属候选目录：{路径；包含候选.page.yaml、专属素材及简短说明}
只在专属目录写入，不改其他页、共享素材、正式清单、核心代码或 skill。
可以在专属目录建立独立的单页检查清单和本地素材副本，用于本页测量。
需要修改共享约定或页面顺序时，提出具体理由，由主 Agent 决定并同步。

【如何填充】
先判断证据能否回答本页问题，写清对象、含义和推理，再选择图文关系与布局。
决定需要哪些公式、符号解释、参考文献、数据图或示意图，包括材料尚未直接提供的
元素。示意图中的点、节点、柱条、颜色和箭头都要有明确含义及依据；图形服务解释。
公式按 skill 使用可编辑原生数学对象，遵守统一符号；正文使用完整句子。
按需选择主证据面板，核对坐标、单位、条件及结论；区分观察、作者解释和补充推测。
缺材料时按 skill 获取有依据的素材或明确占位，说明用途与所缺证据，不制造事实。
不要为了符合预计总结而强化结论。发现缺前提、重复讲解、图不支持总结、规划顺序
不合适时，报告具体位置并提出调整建议；不要悄悄移动页面或替主 Agent 改全局。

【回传】
交回前必须按“页面 Agent 的交回条件”执行本页源稿预检与文字测量，修复字段、
素材、几何和可测文字的错误及溢出，修改后复测。YAML可解析、没有越界或几何
检查通过都不能代替文字检查。使用自己的单页检查项目，不写共享正式清单。
交付候选.page.yaml、使用的专属素材及必要可编辑图稿。
按content.md核对当页文献条目：作者顺序、原始题名、刊物、卷页年及DOI等适用字段
须准确，并回传核验来源；不再用自拟主题加首作/通讯作者替代论文式著录。
作者初稿完整列出，未经用户明确指定不使用et al.或“等”自行省略；空间不足先调布局，
将完整条目交由人类决定作者简写。
简短说明：本页实际总结句、图文如何支持它、证据定位、关键符号与条件、与前后页
的衔接、未解决问题或对主规划的建议，以及实际运行的命令、检查报告路径与结果。
公式等unverified元素逐项说明，不把它们标通过，也不因此跳过其余普通文字。
工具不可用或检查失败时回报受阻，不声称完成。主 Agent 统一整合、复检与批量
最终渲染；减少重复看图不取消本页测量和必要的原图核对。
```

## 回收源稿后，主 Agent 必须做什么

逐页读取实际候选及说明，而非直接接受“完成”或复制负责人结论：

- 本页预检与文字测量是否实际运行，报告是否对应当前源稿与素材？缺检查产物或仍有
  可测文字溢出时交回负责人修复，不将此类候选当作已完成页面统一导出后才处理。
- 这一页实际回答了原定问题吗？公式里的量、图中的对象和方法的作用解释清楚了吗？
- 关键表述能回到原始材料吗？核对关键数字、图解和结论，不能只检查 YAML 几何。
- 当页文献是否按统一论文体例著录，作者、原始题名、刊物、卷页年和标识是否准确，
  核验来源与被引用的具体说法是否对应？格式存在不等于文献核验完成。
- 作者是否完整且顺序一致？出现et al.、“等”或截短名单时，须有用户明确给出的
  保留名单或省略规则，不能由版面压力或期刊体例名称推定。
- 预计总结被修正了吗？是否影响前后页的前提、术语、比较条件或整稿结论？
- 图文表达是否有效，而不是用无定义点阵、表征条或几句话的空大框填满页面？
- 实际内容是否足以单独成页，是否应与相关页合并？若合并，由主 Agent 更新全局
  安排并指定一个负责人重组，不把两个候选直接缩小后拼在一页。

候选有问题时交回该页负责人，携带具体证据；主线问题由主 Agent 更新规划并只通知
受影响页面。不能在未告知负责人的情况下批量改科学解释后沿用原来的自检结论。
采用改动后，重新串读**实际**总结句，检查第 2 页问题交代及方法、结果的前提顺序。

统一整合由主 Agent 串行执行，不让各页负责人并发写同一个项目。正式导入、几何
复检、文字测量和最终视觉检查仍按 production/review 执行；语义检查在导出前先做。
复用同一版最终 PPTX 的可读拼图覆盖整稿，疑点页再放大；本页负责人按需使用这份
渲染修正，不各自全量导出。局部修改只重新派发目标页，主 Agent 核对受影响的衔接。

## 返修 prompt 模板

```text
继续负责第 {页码} 页。当前规划版本与候选：{路径或明确版本标识}。
具体问题：{源稿元素/图中位置与观察；指出与任务或证据的差异}。
核对依据：{原文/原图定位，或实际 PPTX 渲染路径；不能只说“不好看”}。
本轮修改目标：{需要解决的讲解或布局问题，不强制预设版式}。
全局是否调整：{未调整，或给出更新后的本页任务和相邻页依赖}。
保留范围：{已经认可的内容、事实和素材}。继续只写你的专属候选目录。
修改后重跑受影响的本页预检和文字测量，回传修订源稿、当前检查报告路径、实际
总结句、所解决的问题和仍待主 Agent 决定的事项；不能复用修改前的通过结果。
```

独立页面制作的价值在于专注每页的逻辑与表达。它不自动保证科学正确、全局连贯
或视觉合格；主 Agent 对这些最终结果承担整稿责任。没有 subagent 能力时说明实际
限制，不把单 Agent 制作宣称为已执行该工作方式。
