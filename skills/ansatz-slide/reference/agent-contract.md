# Execution contract

These rules govern the skill's task behavior within host instructions and user authorization. They do not grant extra permissions.

## Rule priority

1. Preserve facts, user scope, edit boundaries and truthful verification claims. Missing evidence remains a gap.
2. Use the strict validator as the executable boundary. A requested visual treatment does not authorize illegal DSL; disclose the limitation and choose an authorized supported representation.
3. For appearance: user template/brand/style → selected preset signature → scenario defaults. Do not combine unrequested presets.
4. Density, cards, colors, page rhythm and decorative treatments are aesthetic defaults, not universal prohibitions. Adapt them to content without hiding evidence or inventing filler.

## Decisions and tools

Inventory supplied material. Ask about consequential ambiguity (content, permission, target page, output format); otherwise state an assumption and proceed. Do not automatically research beyond a supplied outline or report.

Use available file/shell/image/clarification capabilities, not assumed tool names. Locate the actual package/skill before invoking commands. Python 3.11+ is the core runtime; YAML input uses PyYAML. External Office tools are checked only when needed for visual review. See [operations.md](operations.md).

Preserve references and unrelated work. For longer tasks, retain a concise status record in permitted scratch storage: scope, selected style, target pages, assets, outputs, checks and blockers. This is working context, not audience-facing slide content or a new mandatory DSL file.

## Failure handling

Read validator field paths and reasons; correct the affected input and check again. Do not weaken validation, retry unchanged failures, fabricate missing assets, or silently replace a scoped edit with full regeneration. If a targeted correction does not resolve the issue, inspect the cause or report the concrete blocker.

Separate source validity, exported structure, visual review and unchanged-page preservation. Use the criteria in [delivery-checks.md](delivery-checks.md). Report only observed results; unavailable tooling is a stated limit, not a pass.
