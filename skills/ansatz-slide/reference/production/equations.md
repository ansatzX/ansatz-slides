# 公式：PowerPoint 原生可编辑数学

出现数学公式或符号时必须全文读取本附录；阅读论文中的公式仍须完整读取并执行
[read.md](../content/read.md)。

## 默认使用原生数学对象

PPTX 中新写的公式、单独的数学符号、变量、上下标、关系符号和含数学记号的单位，
均使用 PowerPoint 原生 Office Math（OMML）。表达式可用 LaTeX 子集作为输入，
但交付对象须为原生数学，不能用 TikZ、LaTeX 栅格化或其他工具生成图片替代。
只有用户明确授权公式图片时才使用图片分支；渲染器不兼容或节省制作时间不是授权。

普通文字框中的 Unicode 希腊字母、拼接上下标和 HTML `sub/sup` 均不能冒充数学
对象。例如采用 `\(\sigma_{\mathrm{opt}}\)`、`\(\tau_{S_1}\)`、`\(R^2\)`、
`\(\mu\mathrm{J}\,\mathrm{cm}^{-2}\)`，而非普通文本 `σopt`、`τS₁`、`R²`。
数学对象内部使用 Unicode 编码属于正常实现，判断依据是实际 OOXML 对象结构。
中文解释继续使用完整句子，数学可以行内混排或独立成段；保持符号和单位一致。
整份 PPTX 必须统一符号，同一概念使用一致的记号；对符号含义或写法有疑问时，可以询问用户。

TikZ 用于几何、机制和推导配图；数据图、原论文科学图中已有的数学标签可随图保留。
这些图内标签不能替代本页需要单独解释或编辑的数学对象，不把整页正文做成图片。

## 从页面需求创建公式

本页用于定义、解释、比较或推理的公式，须从核实的表达式创建并实际插入；不能只
在正文或备注中提及，也不能用论文截图替代。保留原文的符号、编号和限定，说明
变量含义与必要单位。缺少完整表达式时明确缺口，不凭直觉补推导或改符号。

执行“一页事一页毕”：当页排出所用关系、符号说明及具体文献。前页公式、末尾
文献表、图轴小字或 notes 中的源表达式均不能代替当页内容。连续推导可分步展开，
各页保留理解该步所需的关系与条件。

## 当前导出能力与限制

富文本 `\(...\)` 调用有限的 LaTeX 到 Office Math 序列化器，详见
[字段参考](../technical.md)。支持分式、上下标、部分符号及字体命令，
不是完整 TeX 引擎；未知命令当前可能保留为字面文字。制作前核对实际表达式，
不能假定根式、重音、矩阵或 `\hbar` 已实现；不支持时明确报告能力缺口，不转图片。

```yaml
content:
  text: |
    <p>模型使用最低单重激发态寿命 \(\tau_{S_1}\) 进行比较。</p>
    <p>\(R^2 = 1 - \frac{SS_{\mathrm{res}}}{SS_{\mathrm{tot}}}\)</p>
```

此示例只展示语法，具体定义和引用仍须来自当前材料。YAML 块标量原样保留反斜杠；
JSON 每个反斜杠须转义，例如 `"\\(x_i\\)"`。公式内部不能夹富文本标签。

当前 LibreOffice 文字测量不能可靠验证原生 Office Math，因此受检 `page`／`deck`
流程仍会阻止此类候选。遇到这项阻碍应明确说明，不能为了通过检查改成图片、删除
公式或把原生数学直接判为测量通过。原始 `export` 保留原生数学，可用于制作候选：

```bash
ansatz-slide deck preflight ./deck --offline
ansatz-slide export ./deck -o ./native-math-candidate.pptx --offline --transition none
```

原始导出不承担受检流程的文字容纳和最终渲染门槛；字段、素材和几何检查继续有效。
须另用能正确显示实际公式的目标演示软件检查完整 PPTX 的表达式、上下标、分式、
行距及裁切。没有可用目标软件时标明原生数学尚未完成视觉验收，保留候选及源稿。
OOXML 存在 `m:oMath` 只证明创建了数学对象，不证明表达式语义或最终外观正确。

## 用户另行授权公式图片时

仅此情况下可使用已有 `scripts/render_equation.py`，从可信 LaTeX 经 PDF 生成
透明 PNG 并保留 `.source.tex`；本机需 `pdflatex` 和 Poppler `pdftocairo`。
这属于用户选择的图片交付，不宣称可编辑 Office Math。普通页面制作仍按前述原生
数学要求执行；不要为了消除测量或预检提示而自动进入此分支。
