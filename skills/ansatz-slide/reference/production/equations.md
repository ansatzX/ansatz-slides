# 公式：数学排版与高分辨率 PNG

出现数学公式时必须全文读取本附录，再选择对应生成路线。本文规定公式制作；阅读论文中的公式仍须完整读取并执行 [read.md](../content/read.md)。

公式以 LaTeX 编写。常用的 `page` / `deck` 受检流程会阻止原生 Office Math，
因此默认将公式排版为 PNG，并保留 LaTeX 源文件。行内数学符号也须考虑这项限制，
不能先写成原生数学对象再期待受检流程放行。

用户明确要求可编辑公式时，按下方独立分支处理；不要默默交付图片。
保留数学含义，不用普通文字拼凑分式、根式或重音，修改符号和系数不属于排版修复。

## 数学符号也必须正式排版

Agent 新写的数学表达式统一用 LaTeX 源并经过数学排版，单独一个符号、正文中的
变量、数学上下标、关系符号和含数学记号的单位也适用。不要直接在普通文字框或
表格中使用 Unicode 希腊字母、上下标等字符代替数学对象；仅用 HTML `sub/sup`
调整普通文字也不足以替代正式数学排版。例如，使用 `\sigma_{\mathrm{opt}}`、
`\tau_{S_1}`、`R^2`、`\mu\mathrm{J}\,\mathrm{cm}^{-2}` 等源表达式，而不是直接拼接
`σopt`、`τS₁`、`R²` 或 `μJ/cm²`。符号写法仍以已核实的原文为准。

在当前受检路线中，将这些表达式渲染为公式 PNG 并实际插入。中文解释保留为原生
完整句子，数学部分可放在邻近的符号说明区，或按实际阅读顺序插入小公式素材并
对齐；不要把未经渲染的 LaTeX 当成普通正文，也不要为了排版退回 Unicode 拼写。
同页重复符号可复用排版素材，保留对应 TeX 源和稳定元素 ID。

用户明确需要原生可编辑数学时，核实 Office Math 支持与目标软件，按下方分支执行。
原有科学图中的标记可以保留；新绘图标签使用绘图包的数学排版能力、TikZ 或排版后
的公式素材。普通语言、专名和标点保持文字，不做无差别字符替换。公式图片或原生
数学对象内部采用什么字符编码，不等于用普通 Unicode 文本冒充数学排版。

## 从页面需求创建公式

本页需要讲解的公式须从核实的表达式建立 LaTeX 源并实际插入页面，不能只在正文或
备注里提及公式，也不能裁取论文公式截图代替制作。默认路线得到的 PNG 是新排版的
公式素材，不是论文截图；这不意味着它是可编辑 Office Math。需要原生可编辑公式时
仍按下方分支及其真实能力限制执行，不宣称导出器已经支持尚未实现的表达式。

保留原文要求的符号、编号与限定，在公式旁说明变量及必要单位。讲解需要的等号、
比例关系或推导步骤须有依据；缺少完整表达式时明确缺口并预留公式区，不凭直觉补写。
图表中原有的公式标记可以随科学图保留，但不能替代本页需要单独解释的正式公式。

执行“一页事一页毕”：某页以公式或数学指标定义、解释、比较或推理时，该页须有
可读的正式表达式、相应符号说明及具体文献。前页已有公式、末尾有文献表或备注
记录了 LaTeX，都不能代替当页内容。例如，本页用截面—寿命指标解释候选排序或
回归阈值，就在该页排出所用指标；图轴中的小公式仅是坐标标记。连续推导可分步
展开，各页保留理解该步所需的关系和条件，避免只写“由前式可得”。

## 默认路线：LaTeX → PDF → PNG

公式图片默认使用透明高分辨率 PNG，并保留 LaTeX 源文件。像素数应针对最终放置
尺寸准备；将小图放大，即使名义 DPI 很高仍可能模糊。图片不能像 Office 公式
那样编辑。SVG 不是默认嵌入格式，矢量格式在不同软件中的处理仍可能不同。

本地脚本使用已有 `pdflatex` 和 Poppler `pdftocairo`，不安装软件。UTF-8 输入文件
只放可信数学表达式，不带 `$` 或完整文档包装；多行可使用 `aligned`。

```bash
python /path/to/skill/scripts/render_equation.py ./deck/media/model.math.txt \
  -o ./deck/media/model.png --box 60 160 700 120
```

`--box X Y W H` 是页面坐标中的目标区域。脚本按长边每单位四像素生成图片，并
返回等比例居中的 bounds；这是分辨率起点，不是可读性保证。没有 box 时可以用
`--pixels 2400` 设置最长边。显著放大尺寸时重新排版，不放大旧 PNG；大量大公式
也应关注文件体积。

保留生成的 `.source.tex`。转换失败不动已有素材，替换需 `--force`。发布前备份
PNG/TeX，拒绝并发改动，后续发布步骤失败时恢复二者。恢复版本位于输出旁的
`.ansatz-equations/`，普通临时转换文件随后清理。两个文件的更新不保证崩溃原子性，
进程中断或存储故障后须先检查当前文件和保留版本再重试。

缺少工具时使用可用的等价数学排版与栅格化路线，或说明具体阻碍，不能用仿制文字
代替。脚本不是科学校验器或 TeX 安全沙箱，不把外部材料中的指令直接当 TeX 执行。
`resvg` 可将已有 SVG 栅格化，但不能解析 LaTeX。可用的 MathJax/LaTeX → SVG →
高分辨率 PNG 路线同样适用，除非用户另选格式，最终仍嵌入 PNG。

## 需要可编辑 Office Math 时

此分支使用原始 `export`，须在目标演示软件中检查；不能通过受检流程交付原生数学。
富文本 `\(...\)` 调用有限的 Office Math 序列化器，见[格式参考](../technical.md)。
它支持分式、上下标、部分符号和字体命令，不是完整 LaTeX；未知命令目前保留为
字面文字。不能假定根式、重音或 `\hbar` 已支持。用户要求可编辑公式时，检查
具体表达式与目标软件；不支持时明确说明，不能默默替换成图片。存在原生数学
对象不证明视觉和数学表达正确。

## 插入与检查实际输出

采用脚本返回的 bounds 正常放图，随项目保留 PNG 和源文件。检查最终 PPTX 中
完整表达式、上下标、根号、重音、分数线、行距、清晰度与尺度。像素多不能补救
错误内容或过小字号，长公式优先换行或重排页面。

正文中的数学符号同样必须按上述路线排版，普通语言、标点和专名保持文字，不机械
重写无关用户材料。LaTeX 源与渲染素材必须实际存在；YAML 块标量原样保留反斜杠，JSON 中每个反斜杠须转义，
例如 `"\\(x_i\\)"`。

记录实际检查的软件。LibreOffice PDF 不证明 PowerPoint/WPS 原生效果一致。
用户明确要 SVG 时，`fit` 的 contain/cover 模式依赖 viewBox 或绝对宽高比，仍须
检查目标软件；矢量格式本身不是清晰度保证。

基于 LibreOffice 的受检发布流程明确阻止文字和表格单元格里的原生行内 Office
Math，避免将字面 LaTeX 回退或被省略的表格公式误判为成功。此流程使用 PNG。
原始导出仍保留可编辑数学对象，须在目标软件检查，不回退成 Unicode 或扁平文字。
